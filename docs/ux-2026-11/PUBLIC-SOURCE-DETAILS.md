# Public horse details: Sheyhe → Supabase → Core and Modern

The registry previously had an internal Sheyhe detail-gap view, but those values were not exposed on either live horse profile. This release adds a public, horse-only source projection. It does **not** add new master identities or rewrite official registration, ancestry, location or breeding eligibility.

**What changed in the data:** extracted 5,912 dated horse-province observations from a checksum-pinned public profile archive. Most archive columns are deliberately not imported. For uniquely linked, active registry horses, published selected country, province and use labels as Sheyhe described them. Coat, strain and a year-as-published are shown only if the relevant registry field is empty. The public table rejects ambiguous links, unknown/other strain placeholders, unsafe URL forms and unsupported fields. A source province does not prove a present-day address; a published year does not establish an exact birth date or calendar conversion.

**Live checks:** the bounded reader revisits exact source pages, checks robots, requires the horse's name and own pedigree link, stores only selected values and digests, and spaces requests. A changed or missing trait is not silently substituted for an archived fact. Each public field shows either its archive date or its actual recheck date. The separate provenance URL opens Sheyhe's own record. Database/API response dates are observations, not commissioning or certification dates.

**Examples:** Halameh (#10100002) — Sheyhe reports coat `کهر`, strain `حمدانی`, use `مادیان تولیدی`. Kzand (#10100032) — coat `ابرش`, use `سواری آزاد`; the source strain `سایر` (“other”) is not published as a specific strain. Source claims are not evidence of genetic parentage.

**Readbacks:** `receipt.json` breaks out individual fields, distinct horses and which fields were freshly rechecked. `independent-check.json` compares the complete public projection to the pinned CSV and exact page receipts. `bridge-audit.json` rechecks slug and chip/name linkage in the private data. `live-receipt.json` checks the matching application commit, Cloudflare version/assets and live Supabase. `live-check.json` tests actual rendered content and attribution links on both frontends. Source intake, deployed projection, live UI and current-page checks are different counts.

**Known limits:** no evidence of complete partner-system coverage or all pages verified today. The larger Asbdavani detail queue still has pending pages; do not guess the identity of its unnamed horse or join unlinked master records by name alone. Existing analytics/visibility gates are separate from this release. The preceding full suite completed with 2,298 passed, one failed (`offers.test.ts`), ten pending; this release runs scoped tests and does not declare the whole application green. See `RUNBOOK.md` for repeatable intake, review and withdrawal steps.

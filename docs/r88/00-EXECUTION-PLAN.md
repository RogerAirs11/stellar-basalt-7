# R88 execution plan - written before modifications

Scope: audit the supplied R87 source, preserve all five independent presentation implementations, repair high-risk boundaries first, add an honest self-contained demonstrator, and leave an executable continuation plan. This is not an assertion that the product is production-ready.

## Evidence and constraints

- R87 export: 509 source/configuration files; production images, fonts, seed, lockfile, and prior documentation were deliberately excluded.
- Baseline Python suite: 49 passing tests.
- Registry and scientific modules already exist. Do not rewrite their algorithms for visual polish.
- NPM registry DNS is unavailable in this execution environment. Do not represent a transpile check as a full build or a stub as a real provider integration.
- The marketplace detail function bypasses the shared genetics projection. Fix that first.
- Worker response headers deny framing even for the intentionally embedded Classic Registry. Restrict an exception to its same-origin document path only.
- Listing mutations need a state machine, expiry checks, current resource grants, and conflict handling. Inquiry attribution must not silently turn authentication/database errors into anonymous success.

## Ordered implementation

1. Add narrowly scoped response-frame and timestamp policies with executable regression checks.
2. Route marketplace genetics through one allowlisted projection; exclude deleted parent records.
3. Enforce listing state transitions/current grants, prevent inquiry writes to expired/deleted listings, validate public-request origin and authenticated CSRF, handle duplicate active listing races.
4. Add private inquiry-status workflow and typed client method; preserve per-horse grant semantics.
5. Introduce independent compact semantic-token files for non-Heritage frontends. Do not merge their components or import one frontend into another. Preserve touch targets, focus, RTL, reduced motion, and horizontal pedigree scrolling.
6. Add a zero-dependency, explicitly synthetic demo workbench for service discovery, connected horse/pedigree/market records, inquiry demonstrations, and business-model scenarios. No real contact information, credentials, invented official endorsement, live payment, or production writes.
7. Add a public business-model page and discoverable links. Proposed prices must be labeled hypotheses; supplier observations must have source URLs and retrieval date; never treat horse asking prices as proof of willingness to pay.
8. Run available Python, dependency-light TypeScript/runtime, SQL, source-syntax, and browser tests. Record failures and excluded checks verbatim.
9. Produce detailed audit, requirements matrix, risk register, business model, agent task DAG, release gates, migration/deployment notes, changes, and full source archive plus patch/checksums.

## Non-goals in this patch

No live payment gateway activation, unlicensed scraping, fabricated lab verification, clinical advice, genomic prediction, wholesale database rewrite, or claim of completing production service booking. Those require explicit contracts, permissions, stronger tests, and operating owners.

## Acceptance before packaging

The new demonstrator works without the omitted assets. Existing Python tests remain passing. New boundary policies have runnable regression coverage. All changes are listed, all unverified areas are visible, and the source archive contains every original source file (modified where necessary), not just a diff.
